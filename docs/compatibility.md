# 环境与兼容说明

## Skill 与执行工具分开

本仓库只有说明文本和展示资源，没有 Python/Node 运行时、安装脚本、MCP 服务、网络上传或后台任务。保留整个目录即可读取；`SKILL.md` 中的引用相对于文件所在目录解析。

| 工作 | 实际需要的能力 | 缺少时的处理 |
| --- | --- | --- |
| 讨论选题、编排文字、检查声明 | Agent 读取文本与用户材料 | 用户提供可读取材料后继续 |
| 改进作品 | 作品自身的开发或编辑工具链 | 先检查已有工程说明，按作品需要准备依赖 |
| 拍摄真实过程 | 浏览器或桌面操作、截图权限 | 给出待采集步骤；由用户补图或在具备工具的环境继续 |
| 制作 Word / PDF | 对应格式的生成与预览工具、所用字体 | 选择环境中可用工具；最终格式未预览时明确说明 |
| 压缩包核对 | 解压、文件读取能力 | 在可解压环境验证后再声明完成 |

先检查当前环境已有工具。需要安装软件时说明用途和安装范围，遵循用户现有授权及环境权限。不要为了使用这个 Skill 自动安装整套开发环境，或修改全局配置。

## Agent 加载

Codex 与 Claude Code 可使用其原生技能目录，见 README。两者均以 `SKILL.md` 的名称和描述发现技能；具体加载与界面表现受产品版本影响。`agents/openai.yaml` 仅补充 Codex 显示信息，不是执行依赖。

DeepSeek harness（dsh）的官方文件系统 Skill 提供方支持项目 `.dsh/skills`、`.agents/skills`，以及个人 `$DSH_HOME/skills`（默认 `~/.dsh/skills`）和 `$DSH_AGENTS_HOME/skills`（默认 `~/.agents/skills`）。把整个仓库置于其中一个根下的 `campus-ai-competition/` 即符合目录包结构；只发现直属 `<name>/SKILL.md`，不递归寻找嵌套技能。

这些目录需要会话启用 Skill 注册表与文件系统提供方；模型调用由 `dsh-tool-skill` 提供。定制配置中的 `includeDefaultRoots: false` 可关闭默认目录，此时应检查所在环境已有设置，不能盲目反复复制。上游仍在快速迭代，安装后确认会话能发现名称并实际读取正文。

依据：2026-10-22 核对的[官方说明（固定提交）](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/skill/skill-filesystem/README.zh.md)。这是官方文档确认，本仓库尚未在 dsh 中运行完整比赛流程。若原生加载不可用，可要求 Agent 显式读取 `SKILL.md` 及相关参考文件；此时属于手动上下文接入。

如果 Agent 不支持本地文件，可将 `SKILL.md` 与当前步骤所需参考内容一并提供，并用清晰文件名区分。只粘贴入口而遗漏被引用的写作或环境规则，不能等同于完整安装。

## 换机检查

1. 确认 `SKILL.md` 位于技能目录第一层，参考文件完整且可读取。
2. 用一个虚构比赛通知试调用，确认能识别要求并列出仍影响结果的决定。
3. 根据实际交付，验证一次截图和一次目标文件预览；检查中文字体是否缺字。
4. 用独立演示目录和合成数据检查公开截图，不把个人账号和隐私画面迁入示例。

以上是可复查的安装和能力检查；本次文档检查不能替代另一台电脑上的实际演练。
